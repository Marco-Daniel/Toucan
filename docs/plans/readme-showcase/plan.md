# Plan: README showcase

## Goal

Make the README show Toucan, not just describe it: a hero GIF up front, then one section for every feature with a screenshot. The images are generated by a script, so they can be refreshed whenever the UI changes (→ [0001](decisions/0001-present-toucan-as-a-showcase-first.md)).

## Non-goals

- No feature changes.
- No Marketplace or Open VSX publishing; that's for a later iteration.
- No GIFs beyond the hero.

## Approach

**A capture script** (→ [0002](decisions/0002-capture-the-readme-screenshots-with-a-script.md)), e.g. `pnpm screenshots`:
- It builds the VSIX and starts an **isolated** VS Code: its own user-data-dir and extensions-dir, never a developer's profile.
- It uses a demo setup: a few demo repos with distinct colors and glyphs, and neutral names, with no real projects or paths.
- It drives VS Code the way the smoke tests did, and writes PNGs to `media/readme/`.
- It also records the frames for the **hero GIF** (→ [0003](decisions/0003-open-the-readme-with-one-hero-gif.md)): short and small, for example three windows in different colors with focus moving, plus Set Color's live preview.

**The README** (→ [0004](decisions/0004-document-every-feature-in-the-readme-with-screenshots.md)):
- the hero GIF at the top;
- one section per palette command (Set Color, Pick Preset Color, Set Glyph, Clear Color, Toggle Sidebar Block, the search emoji) and per setting;
- sections for the status bar, the sidebar block and the experimental search emoji;
- each with its screenshot.

## Components

- **The capture script** (a `.mts` under `scripts/`), plus its demo fixture. Keep the pure parts unit tested, as with other scripts. A devDependency for GIF encoding is allowed if needed.
- **`media/readme/`**: the generated PNGs and the GIF. They aren't packaged: `.vscodeignore` is an allowlist, and `check:vsix` keeps its 8 files.
- **README.md**: the restructured feature tour. The docs-sync rule applies.

## Risks

- **Private details in an image.** Window titles, tab names, paths, usernames or EXIF data could leak. The demo setup uses neutral names, metadata is stripped, and reviewers inspect every image.
- **Repo weight.** Keep the GIF short and the PNGs optimised; reviewers check the sizes.
- **Flaky capture.** Driving a real VS Code is timing-sensitive, so the script waits on events, not fixed sleeps.

## Open questions

- The GIF encoder (a small devDependency, or ffmpeg if present): the implementer decides.
