# Plan: Toucan v1

## Goal

Toucan is a VS Code extension (`marco-daniel.toucan`) that shows at a glance which repository a window has open, in the spirit of Peacock and Kingfisher. Colors are configured once, by repo (workspace folder) name, in the user's own settings. Nothing is ever written into the opened repository, and each window stays recognizable even when it is not focused.

## Non-goals

- Writing `.vscode/settings.json` or any other file inside the opened repo.
- Modifying the VS Code installation or relying on unsupported workbench patching.
- Coloring surfaces beyond those listed below (title bar, activity bar, status bar background, editor decorations) in v1.
- Animated color transitions.
- Per-folder colors in multi-root windows (v1 uses the first folder).
- Coloring all status bar text and/or background in the focused window (`statusBar.*` keys). Possible later as an opt-in using the same focus guards as the Command Center.
- Marketplace publishing in v1 (local VSIX only), but nothing should block it later.

## Approach

VS Code has no per-window color API: `workbench.colorCustomizations` is window-scoped and only differs per window through workspace settings, which live in the repo. Toucan therefore layers several signals ([0002](decisions/0002-apply-command-center-color-in-user-scope-for-focused-window.md)):

1. **Command Center color, focused window only.** Toucan merges its `commandCenter.*` keys into the user-scope `workbench.colorCustomizations` when a window gains focus, and clears them on blur only if this window still owns them. It owns the whole `commandCenter.*` namespace and never touches other keys ([0003](decisions/0003-toucan-owns-the-commandcenter-namespace.md)).
2. **Status bar indicator, always, every window.** A left-aligned item with a glyph from Toucan's own icon font plus the repo name, colored with the repo hex. This is the signal that survives blur, with no settings writes ([0005](decisions/0005-always-show-a-status-bar-glyph-and-repo-name.md)). The glyph shape is set per repo, default square ([0012](decisions/0012-make-the-glyph-a-per-repo-setting-defaulting-to-square.md)).
3. **Opt-in: secondary sidebar color block** (Kingfisher style) as a webview view ([0006](decisions/0006-offer-an-opt-in-secondary-sidebar-color-block.md)).
4. **Opt-in, experimental: emoji in the Command Center label** via `window.title` and a per-window context key ([0007](decisions/0007-offer-an-experimental-emoji-in-the-command-center-label.md)).

Config is one map in user settings keyed by folder name ([0001](decisions/0001-store-colors-in-user-settings-keyed-by-folder-name.md)). Missing colors are derived from the background with culori ([0004](decisions/0004-derive-missing-colors-with-culori.md)). Tooling is as modern as VS Code allows ([0010](decisions/0010-use-a-modern-toolchain.md)); distribution starts as a local VSIX ([0011](decisions/0011-ship-as-local-vsix-with-split-ci-workflows.md)).

## Configuration

```jsonc
// user settings.json
"toucan.repos": {
  "webshop": "#e91e63",                     // string = background, rest derived
  "toucan": {
    "background": "#1b5e20",                // required
    "foreground": "#ffffff",                // optional overrides…
    "border": "#2e7d32",
    "glyph": "heart",                       // optional, default "square" (0012)
    "sidebarBlock": "unfocused"             // optional, overrides the general visibility (0013)
  }
},
"toucan.sidebarBlock.enabled": false,       // opt-in (0006)
"toucan.sidebarBlock.style": "full",        // "full" | "muted" (0013)
"toucan.sidebarBlock.visibility": "always", // "always" | "unfocused" (0013)
"toucan.experimental.searchEmoji": false    // opt-in, experimental (0007)
```

These setting names are fixed. Keys and command ids are generated by vscode-ext-gen.

Overridable keys map to `commandCenter.*`: `background`, `foreground`, `activeBackground`, `activeForeground`, `border`, `activeBorder`, `inactiveForeground`, `inactiveBorder`. Any color string culori can parse is accepted; values are written as hex.

Glyphs (curated, enum-validated): `square` (default), `bar`, `pill` from Toucan's font; `circle`, `double-circle`, `heart`, `star`, `check-circle` from built-in codicons ([0012](decisions/0012-make-the-glyph-a-per-repo-setting-defaulting-to-square.md)).

Repos without an entry: Toucan removes its keys and shows no indicator ([0008](decisions/0008-clear-toucan-keys-for-unconfigured-repos.md)).

## Components

Pure modules (no `vscode` import, unit tested with vitest):

- **config parser**: reads the raw `toucan.repos` value, normalizes string/object entries, validates colors via culori and the glyph against the curated list, reports invalid entries.
- **color deriver**: from a background (plus optional overrides) produces the full `commandCenter.*` set. Foreground by WCAG contrast (black/white), hover and border via OKLCH lightness shift (lighter on dark, darker on light), inactive variants via alpha.
- **customizations merger**: given the current global `colorCustomizations` object and Toucan's desired keys, returns the new object, touching only `commandCenter.*`. Also returns "no change" so callers can skip writes.
- **emoji mapper**: maps a hex color and glyph to the nearest emoji of a matching shape (squares, circles, heart; star, bar and pill use squares, because ⭐ only comes in yellow).
- **glyph resolver**: maps a glyph name to its `$(…)` icon id and to an SVG used for tooltip and sidebar swatches.

VS Code-facing modules (thin):

- **repo resolver**: picks the first workspace folder's name and looks up its entry.
- **focus coordinator**: listens to `onDidChangeWindowState`, reacts only to real `focused` transitions (ignores `active` toggles), writes on focus, and on blur (debounced) clears only if the stored owner marker is still this window's. Cleans up leftovers from crashed windows on startup and clears on `deactivate`.
- **status bar indicator**: one item (`createStatusBarItem` with a stable id, left, max priority), `$(<glyph>) repo-name`, `color = background hex`, markdown tooltip with an SVG data-URI swatch in the repo's glyph shape, hex value and action links, accessibility label, click opens Set Color.
- **sidebar block** (opt-in): `secondarySidebar` view container with a webview view, `enableScripts: false`, strict CSP, body painted with the repo color and the glyph drawn large in the middle, repo name underneath. Style `full` (solid color) or `muted` (~25% alpha fill, full-color glyph and name). Visibility `always` (revealed on startup; once you close it, it stays closed for that repo until you reopen it) or `unfocused` (revealed on blur; on focus the secondary sidebar is closed again only if Toucan opened it), set globally and overridable per repo ([0013](decisions/0013-make-the-sidebar-block-style-and-visibility-configurable.md)). Always revealed with `preserveFocus: true`; never switches other views.
- **search emoji** (opt-in, experimental): ensures `window.title` contains `${activeRepositoryName}` (one-time global write; a dialog asks when the setting is turned on, Cancel turns it back off, and the previous value is restored when it's turned off, [0015](decisions/0015-ask-before-changing-window-title.md)), then sets the `scmActiveRepositoryName` context key to the emoji (or emoji + repo name when the user's own title already used the variable, [0007](decisions/0007-offer-an-experimental-emoji-in-the-command-center-label.md)), reasserting after git/SCM, editor and focus events.
- **commands**: *Set Color for This Repo* (input with validation and live preview), *Pick Preset Color* (quick pick of the toucan-themed palette with live preview, [0014](decisions/0014-ship-a-toucan-themed-preset-palette.md)), *Set Glyph* (quick pick of the curated glyphs with live preview), *Clear Color*. These write the `toucan.repos` entry in user settings. *Toggle Sidebar Block* opens or closes the block in the current window ([0013](decisions/0013-make-the-sidebar-block-style-and-visibility-configurable.md)).
- **icon font**: SVG sources for `square`, `bar` and `pill` plus the generated `.woff`, both committed; a pnpm script regenerates the font (Node-based generator as devDependency). Registered through `contributes.icons`; `$(circle-large-filled)` is the fallback.

## Data flow

1. Activation (`onStartupFinished`), config change (`toucan.*`) or window focus triggers a refresh.
2. Repo resolver → config parser → color deriver produce the desired colors for this window.
3. Status bar, sidebar block and search emoji render locally from those colors (per window, no settings).
4. If focused: merger computes the new global `colorCustomizations`; write only on change, then record this window as owner.
5. On blur: after debounce, re-read the global value; if the owner marker is still ours, remove Toucan's keys.

## Risks

- **Status bar contrast**: only the glyph/text color is ours; a dark color on a dark status bar is hard to see. Consider a contrast warning.
- **Focus races**: blur and focus writes from two windows can overlap briefly. Mitigated by the owner marker; newest focus wins.
- **settings.json churn**: every focus change writes user settings. Mitigated by skipping no-op writes and ignoring `active` toggles.
- **Emoji hack fragility**: relies on an undocumented context key and SCM rewriting it (brief flicker). Kept opt-in and labelled experimental.
- **Leftover colors** after crash or uninstall: startup cleanup plus `deactivate` clearing.
- **culori bundle size**: use tree-shakable function imports only.
- **Sidebar `unfocused` mode**: if another view such as Chat was already open in the secondary sidebar, Toucan can't detect it and closes the sidebar on focus. Accepted for v1 because the mode is an opt-in; the setting description warns about it, and `always` mode isn't affected ([0013](decisions/0013-make-the-sidebar-block-style-and-visibility-configurable.md)).
- **Agents control compact mode** (VS Code 1.139 default) hides the Command Center background. Toucan offers once to switch it to `badge` ([0016](decisions/0016-offer-to-switch-agents-control-to-badge.md)).
- **Comments in settings**: Toucan edits its exact keys in settings.json to keep comments, only when the file provably matches VS Code's view; otherwise it falls back to `update()`, which drops comments ([0017](decisions/0017-edit-settings-in-place-to-keep-comments.md)).
